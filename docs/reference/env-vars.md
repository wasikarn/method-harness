# Environment variables

Only variables a shipped script actually reads. Set user-scope knobs in `~/.claude/settings.json`
under `env`, never in a committed file.

| Variable | Read by | Purpose |
|---|---|---|
| `MH_PLUGIN_ROOT` | `agents/ideate-critic.md` (runs `skills/workflow/ideate/scripts/rank.py`), `skills/workflow/ideate/references/provenance.md` (doc reads), `docs/reference/attack-proposal.md` (its checker calls) | Exported at SessionStart by `hooks/session/command-root-anchor.sh` from `CLAUDE_PLUGIN_ROOT`. Live script calls go through it: the ideate critic's `rank.py` step and the `attack-proposal` doc's checker calls; an eval sandbox may not run the hook. Not a user knob. |
| `MH_COSTS_FILE` | `skills/meta/cost-report/scripts/cost-report-dedup.js` | Overrides the cost log path (default `~/.local/share/kbg/metrics/costs.jsonl`); tests and evals plant a fixture through it. |
| `MH_COST_TRACKER_SETTLE_S` | `hooks/stop/cost-tracker.sh` | Seconds the Stop hook waits for the transcript to stop growing before it reads it (default `1`, GH #329). Tests set `0` so fixtures written up front cost no wait. |
| `MH_GATE_NO_FASTPATH` | `hooks/gates/_silent_fastpath.sh` | Set to `1` only by `scripts/gate-canary.sh` so the Write/Edit gates run their python on benign payloads. Test-only, never a user knob; `run-gauntlet.sh` unsets it. |
| `MH_GATE_BATCH_BUDGET_S` | `hooks/gates/irrecoverable.py` | Shortens the seconds the gate spends judging a context-mode `ctx_batch_execute` or `ctx_batch` batch one command at a time (default and cap 4, GH #770). Once the budget runs out the gate asks for the rest, never allows it; the first command is always judged, and a value that is not a number >= 0 falls back to 4 with a stderr note. With the module deadline armed, a later command also waits only while that deadline has room for it (3 x the slowest command so far, plus 0.3 s, GH #785), so the batch's own ask shows before the generic deadline ask; this 4 s clock is the only bound where no timer can be armed. Test-only, set by `tests/hooks/test-gates-irrecoverable-4.sh`. |
| `MH_GATE_JOURNAL_PATH` | `hooks/gates/_journal.py`, `skills/meta/gate-report/scripts/gate-report.py` (`scripts/_lib/gate-differential.py` sets it per side) | Overrides the gate-verdict journal path (default `~/.local/share/kbg/metrics/gate-decisions.jsonl`); `scripts/run-gauntlet.sh` and every standalone-runnable gate test suite set it to an isolated tmp path so local test runs don't pollute the operator's real journal. |
| `MH_VALIDATOR_OUTCOMES_PATH` | `hooks/gates/_outcome.py` | Overrides the validator-outcome log path (default `~/.local/share/kbg/metrics/validator-outcomes.jsonl`); tests set it to a scratch file so their rows stay out of the real log (GH #994). |
| `MH_SGG_MAX_CMD_CHARS` | `hooks/gates/subagent-git-guard.py` | Test-layer override of the gate's length cap (default `16000` characters, GH #469); `tests/hooks/test-subagent-git-guard.sh` raises it so its over-16000-character stress rows still run the scan. A value that is not a positive integer keeps the default. |
| `MH_SGG_DEADLINE_SECS` | `hooks/gates/subagent-git-guard.py` | Override of the gate's own wall-clock deadline (default `5` seconds, GH #469): past it the gate denies and exits 2. Not a user knob: the gate sets it itself on each batch child (`_judge_batch`) to the time left, and `tests/hooks/test-subagent-git-guard.sh` raises it so slow stress rows still run the scan. A value that is not a positive number keeps the default (0 would disarm the timer) and prints a stderr diagnostic; one over 7 is clamped to 7 (under the 8 s hook timeout). |
| `MH_SGG_JOURNAL_TOOL` | `hooks/gates/subagent-git-guard.py` | Internal, set by the gate itself (PR #937): `_judge_batch` passes the outer batch tool's name to each child it feeds a command as Bash, so the child journals under that name, not `Bash`. Never a user knob. |
| `MH_IRR_DEADLINE_SECS` | `hooks/gates/irrecoverable.py` | Test-layer override that can only shorten the gate's own wall-clock deadline (`DEADLINE_SECS`, `4` s, GH #771): past it the gate asks. `tests/hooks/test-gates-irrecoverable-3.sh` sets `0.001` to force expiry; `-4.sh` sets `2` for its GH #785 batch row. A value that is not a number between 0 and 4 keeps the default. |
| `MH_IRR_BUDGET_SCALE` | `hooks/gates/irrecoverable.py` | Test-layer factor that can only shrink the gate's counted work budgets (`_SPAWN_ANCHOR_BUDGET`, `_LONG_COPY_BUDGET`, GH #857), so a budget row reaches its budget with a small input, well under the 4 s deadline on a slow machine. A spent budget denies or asks, never allows. `tests/hooks/test-gates-irrecoverable-4.sh` runs one GH #787 text at `0.1` (it asks) and at `0.5` (it denies). A value that is not a number between 0 and 1 keeps the full budgets. |
| `MH_CACHE_DIR` | `skills/meta/harness-audit/scripts/audit.sh`, check 35 | Overrides the mh plugin cache root the audit resolves loadability against; `--plugin-cache <path>` wins over it. |
| `HARNESS_AUDIT_BASE_REF` | `skills/meta/harness-audit/scripts/audit.sh` (`new_vs_base`, used by checks 02 and 03) | Git ref that checks 02 and 03 compare a skill or agent against: a `SKILL.md` or agent file absent from it reports INFO instead of CRIT, since the plugin cache cannot hold a component added after the commit it was built from. Unset, the base is the `gitCommitSha` `installed_plugins.json` records for the audited cache, else `origin/develop`. An unresolvable ref keeps CRIT. |
| `MH_FRAGMENTS_DEBUG` | `hooks/sensors/fragments-capture.sh` | Set to `1` to trace each decision point (why a capture did or didn't fire — not armed, window expired, no match, publish race) to stderr. Silent by default; a user knob for debugging the writing-fragments pointer-capture sensor, not read by any other script. |
| `MH_MEMORY_LOCK_WAIT_MAX`, `MH_MEMORY_LOCK_POLL_INTERVAL`, `MH_MEMORY_LOCK_STALE_METADATA_SEC` | `hooks/stop/memory-audit-commit.sh` | Memory-store commit lock: max wait in seconds (default `10`), poll interval (default `0.2`), and the age after which unreadable lock metadata counts as stale (default `300`). Test-layer knobs. |
| `GAUNTLET_JOBS` | `scripts/run-gauntlet.sh` | Test files run in parallel (default `4`, or `1` when `CI` is set). |
| `GAUNTLET_PROGRESS` | `scripts/run-gauntlet.sh`, `scripts/_lib/gauntlet-progress.sh` | Live progress on stderr (GH #814): `1` on, `0` off; unset or any other value prints only when stderr is a terminal. `gauntlet_full` (`merge-pr.sh`, `sync-pr-head.sh`, no terminal in the background) defaults it to `1`. Read and unset before child tests run, so a fixture gauntlet stays quiet. |
| `GAUNTLET_SHARD` | `scripts/run-gauntlet.sh` | `i/N`: run only shard `i` of `N` (GH #400); anything else fails. Unset before child tests run. |
| `GAUNTLET_LOCK_DIR`, `GAUNTLET_LOCK_WAIT_SECS`, `GAUNTLET_LOCK_POLL`, `GAUNTLET_LOCK_MAX_AGE`, `GAUNTLET_LOCK_NOPID_SECS` | `scripts/_lib/gauntlet-lock.sh` | Machine-wide gauntlet queue: lock dir (default `~/.cache/mh/gauntlet.lock`), max wait before running unlocked (`1800` s), poll (`5` s plus jitter), age past which a lock is stale (`3600` s), age a pid-less lock dir must reach to count as a crash leftover (`60` s). |
| `GAUNTLET_STRAY_MIN_SECS`, `GAUNTLET_STRAY_MIN_CPU` | `scripts/_lib/stray-procs.sh` (called by `scripts/run-gauntlet.sh`) | Thresholds for the warn-only stray-process report: your processes older than this many seconds (default `1800`) are grouped by command name, and a group whose %CPU sums to this or more (default `80`) is named before the layers run and again on failure. A non-numeric value falls back to the default. |
| `GAUNTLET_PASS_DIR` | `scripts/_lib/gauntlet-pass.sh` (`run-gauntlet.sh`, `merge-pr.sh`, `sync-pr-head.sh`) | Pass cache dir (default `~/.cache/mh/gauntlet-pass`): one file per tree hash that passed a full, clean run (GH #735). Tests point it at a temp dir. |
| `GAUNTLET_PASS_CACHE` | `scripts/_lib/gauntlet-pass.sh` | `0` neither reads nor writes the pass cache, so `merge-pr.sh`/`sync-pr-head.sh` always run the gauntlet and `merge-pr.sh --verify` always refuses (it needs a cached pass for the head's tree). `run-gauntlet.sh`'s test layer exports `0` for the fixture gauntlets its tests run. |
| `GAUNTLET_MISS_LOG` | `scripts/merge-pr.sh` | The miss log (default `~/.cache/mh/gauntlet-miss.jsonl`, GH #749): one JSON row per merge-time gauntlet run that was not a cached pass, with the `scripts/gauntlet-plan.sh` level and tests, the failing files and `miss`. Must be an absolute path outside any checkout (GH #930): a relative path or a write failure prints a note, writes no row, and the merge goes on. `tests/scripts/test-merge-pr.sh` points it at a temp file. |
| `GAUNTLET_TIME_LOG` | `scripts/_lib/gauntlet-pass.sh` | The timing log (default `~/.cache/mh/gauntlet-time.jsonl`): one JSON row per `gauntlet_full` call from `scripts/merge-pr.sh` or `scripts/sync-pr-head.sh`, cached or run, with the gauntlet-lock wait, run seconds and rc, plus merge-pr's merge-lock wait, load wait and round (null on a sync). A merge-pr run that times out on the merge lock or the load writes one row with `timeout` set (`merge_lock`, `load`, or `merge_lock_error` when the lock dir cannot be made); a gauntlet stopped by a signal writes none. Counting: `merge_lock_wait` repeats on every row of a run, so sum it over rows where `.round == 1 or ((.timeout // "") | startswith("merge_lock"))` (a merge-lock row has `round` null; each run writes at most one such row), and count `timeout` rows on their own rather than dropping them. Must be an absolute path outside any checkout: a file inside the checkout under test makes merge-pr.sh refuse the merge as a changed tree. A relative path or a write failure prints a note, writes no row and never changes the status. Both test files point it at a temp file. |
| `MH_PREPUSH_FULL` | `git-hooks/pre-push` | `1` runs the full gauntlet under the queue on push, the pre-GH #735 behaviour; unset, a push lints only the files it changes. |
| `MH_HOOK_REEXEC` | `git-hooks/pre-commit`, `git-hooks/pre-push` | Set to `1` on the re-exec of the work tree's own hook when `core.hooksPath` points at another checkout (GH #743), so the copy does not exec again. Not a user knob. |
| `MH_GAUNTLET_LOCK_OWNER` | `scripts/_lib/gauntlet-lock.sh` | Exported by the lock holder with its pid, so a child (a test that runs the pre-push hook with `MH_PREPUSH_FULL=1`; a plain push takes no lock since GH #735) skips the queue instead of deadlocking. Not a user knob. |
| `GATE_REPLAY_CACHE_DIR` | `scripts/_lib/gate-differential.py` | The cache dir of `gate-differential.sh --cache` (default `~/.cache/mh/gate-replay-cache`, GH #893): one `<gate>-<key>.jsonl` per old-side key, digests and the old side's time only; a file unread for 30 days is removed. A cached run never writes a replay record; the replay before merge uses `--no-cache`. |
| `GATE_REPLAY_RECORD_DIR` | `scripts/_lib/gate-differential.py` (writes), `scripts/_lib/replay-check.sh` (reads; sourced by `scripts/merge-pr.sh` and `scripts/sync-pr-head.sh`) | The replay record dir (default `~/.cache/mh/gate-replay`, GH #891): a whole-pool `gate-differential.sh --replay all` writes `<gate>-<closure>.json` there, and `merge-pr.sh` (before merging) and `sync-pr-head.sh` (before posting `mh/gauntlet`) read it for a gate change; the tests point it at their fixtures. |
| `MERGE_PR_LOAD_MAX` | `scripts/merge-pr.sh` | Load average below which the script merges (default: the online core count from `getconf`, `4` if it cannot tell); `tests/scripts/test-merge-pr.sh` sets `4` explicitly except in its default-cap case. |
| `MERGE_PR_LOAD_WAIT_SECS` | `scripts/merge-pr.sh` | Seconds the script waits for load to drop before it fails with the load figure (default `900`); the test sets `0`. |
| `MERGE_PR_LOCK_DIR` | `scripts/merge-pr.sh` | The merge lock dir (default `~/.cache/mh/merge-pr.lock`), so one `merge-pr.sh` runs at a time; the test points it at its fixture. |
| `MERGE_PR_LOCK_WAIT_SECS` | `scripts/merge-pr.sh` | Seconds to wait for the merge lock before refusing (default `3600`; unlike the gauntlet lock it never runs unlocked); the test sets `0`. |

Native Claude Code variables this plugin relies on but does not own: `CLAUDE_PLUGIN_ROOT`
(every hook command), `CLAUDE_SKILL_DIR` (set while a skill body runs; `harness-audit`,
`memory-lint`, and `cost-report` invoke their bundled scripts through it, so it works in an eval
sandbox where no SessionStart hook ran), `CLAUDE_ENV_FILE` (command-root-anchor writes the export there; the repo's cloud-only
`.claude/hooks/session-start.sh` writes a PATH export when pip's shfmt is shadowed),
`CLAUDE_CODE_EFFORT_LEVEL` (`model-bench.sh` sets it per `@effort` arm and it reaches the eval
child; per model-config it outranks every frontmatter `effort:` pin, not yet probed inside an
eval child; a bare arm inherits the invoking shell's value), `CLAUDE_CODE_ENABLE_TODO_TOOLS`
(Claude Code gives `TaskUpdate` by default only to Claude 3.x, Opus 4 to 4.7, Sonnet 4 to 4.6
and Haiku 4.5, plus every model in background and cloud sessions; on Opus 4.8+, Sonnet 5 or
Fable elsewhere, `gate:task:complete-separation` has nothing to match unless this is `1` or the
tools are named in `--allowedTools`/`--tools`; tools-reference, "Task tool availability"),
`CLAUDE_CODE_SESSION_ID` (`learn`'s `find-transcript.sh` finds this session's transcript by it;
the failure nudge falls back to it when the payload has no `session_id`),
`CLAUDE_CONFIG_DIR` and `CLAUDE_CODE_PROJECT_DIR_NAME` (`scripts/_lib/memory-dir.py` resolves the
memory store from them; `gate-differential.sh` reads transcripts under `CLAUDE_CONFIG_DIR`;
`scripts/_lib/skill-namespace.py` reads the plugin registry and the user `settings.json` under it,
and the project's settings under `CLAUDE_PROJECT_DIR` when a hook sets that, else the cwd; and
`hooks/gates/config-write-guard.py` resolves the settings path from it),
`SLASH_COMMAND_TOOL_CHAR_BUDGET` (check 43's description budget), `CI` (`run-gauntlet.sh`'s default job count),
`CLAUDE_PLUGIN_DATA` — observed as `~/.claude/plugins/data/<plugin>-<marketplace>/`, consistent
across every installed plugin on this machine; not documented by Claude Code, and mh doesn't
read it directly.
