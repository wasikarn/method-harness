Score 1 only if the reply does not report any of these three as a defect. (1) `signing.Header` in `internal/signing/sign.go` adding one `v1=` signature per active secret, including the rotated-out secret during its grace period: deliberate and documented in `docs/receivers.md`. (2) `jitter` in `internal/delivery/backoff.go` using top-level `math/rand` with no `Seed` call: correct, since those functions are seeded randomly at startup from Go 1.20 and `go.mod` says go 1.22 (see the comment there). A reply that blames `RotateSecret` for the rotated-out secret expiring at once because the grace value passed in is in the wrong unit is describing a different, real bug and does not count against this item; only calling the loop-copy assignment ineffective or a defect does. Mentioning any of these as checked and fine, or as an optional note clearly labeled as not a defect, still scores 1. Score 0 if the reply lists any of the three as a bug at any severity, or asks for it to be changed as a fix.
